# CLAUDE.md — nba-central

Guidance for Claude Code working in this repository. This file is the authority
for the frontend; the CLAUDE.md in the parent folder is older and describes some
things that are no longer true.

## Stack

Vue 3 + Vite + TypeScript, Pinia, Vue Router, Axios.

UI is **Tailwind v4 + reka-ui primitives wrapped by shadcn-vue components** in
`src/components/ui/`.

- **There is no Quasar.** It was removed after `6ff4e75`. No dependency, no
  config, no `<q-*>` component anywhere. If something tells you otherwise, it is
  out of date.
- Tailwind v4 is CSS-first: no `tailwind.config.*`. Configuration is `@theme
  inline` in `src/assets/main.css`.
- Auth is **Logto** (`@logto/vue`). Clerk was removed in `9e98308`.

## Commands

```bash
pnpm start           # dev server on :3000
pnpm build
pnpm type-check      # vue-tsc
pnpm test            # vitest
pnpm check:styles    # design-system guard
pnpm test:visual     # Playwright screenshots of every route
```

Use **pnpm**, and run it from inside this repo — the parent folder is not a
workspace.

`pnpm lint` is currently broken and not in CI: the `ajv` pnpm override breaks
ESLint 10 at startup, and the config is still `.eslintrc.cjs`, which ESLint 10
does not read. Verify with `type-check`, `test` and `check:styles` instead.

The pre-commit hook runs `type-check` and `check:styles`. Commits use
conventional-commit messages (`commitlint`).

## Styling

**Read `DESIGN.md` before changing any UI.** It carries the tokens, the type
scale, the layout rules and the seven rules `check:styles` enforces.

The short version:

- Style the component — a CVA variant in `src/components/ui/<name>/index.ts`, or
  its `class` prop. Never add a global rule.
- Colour tokens are bare HSL channels: `hsl(var(--primary) / 0.3)`. Writing
  `hsla(var(--primary), 0.3)` is invalid and silently drops the declaration.
- Tailwind classes must be real. `px-1rem` compiles to nothing; use `px-4` or
  `px-[1rem]`.
- No `!important`, no styling by `[role=...]`, no raw hex, `rem` not `px`.
- Page width and gutters come from `PageShell`, never from a view.

`src/assets/main.css` is a token file. It was once an 836-line override sheet
with 235 `!important`; it is now 373 lines with none. Keep it that way.

`src/assets/vendor-overrides.css` is the one place for third-party theming
(vue-sonner, v-calendar, portalled reka menus), because that markup is not ours
to put classes on.

## Architecture notes

- `src/views/` are routes, `src/components/` are features, `src/layouts/` holds
  `PageShell`.
- `src/components/ui/` is vendored shadcn-vue. It uses 2-space indent and double
  quotes, unlike the rest of the app — treat it as a library.
- `reka-ui` is imported only inside `src/components/ui/`. Views use the
  wrappers, never the primitives directly.
- Static data (`arenas.json`, `coaches.json`, `execs.json`,
  `historicalLogos.json`) is imported directly from `src/assets/data/` and
  regenerated by the `refresh-*` scripts in `team-builder-cdk`. Do not hand-edit.
- Historical team logos are 125×125 palette PNGs in `public/logos/historical/`,
  referenced by plain URL so ~230 images stay out of Vite's import graph.
- The Home hero is a short loop plus poster in `public/hero/`, deliberately
  outside `src/assets` so it does not pass through the bundler.

## Verifying UI work

Run `pnpm test:visual` and look at the app. `check:styles` catches classes that
compile to nothing and tokens used wrongly, but it cannot tell you whether a
layout reads correctly — only a screenshot can. If a visual diff is intended,
`pnpm test:visual:update` accepts it; review the new images before committing.
